## 1. 总裁决：CHANGES

1. **P0｜未确认信息仍以确定事实展示。** 大纲 §8.1 明列“第一头 01:56/01:57、S2 分路确认”待修正，但三版均写死 `01:57` 和“打野”。应在对应位置写「待核实」，确认后再填值；页尾“以最终版为准”不能替代逐项标注。
2. **P0｜奖励与核对日期缺少可追溯依据。** B 写“2.6× 速通奖励结算”，三版写“2026-10-28 核对”，但本次审阅文件未提供对应规则、结算凭据或核对记录。不能据此断言编造，但不能批准为已确认事实：奖励写「待公布」或「待核实」，日期未确认写「待核实」，补证后恢复。
3. **P0｜公开标签违反大纲自己的发布规则。** 三版均展示“独狼强开”“风险型 · 一局初判”，未附“五组阈值全中”的通过证据。删去未经验证标签，改为“标签：数据不足”；“一局初判”不能作为公开不稳定标签的豁免。
4. **P0｜自填发布范围可能越过隐私红线。** 大纲允许自述、名场面和代表英雄，但未约束输入内容与导出内容。明确禁止发布真实姓名、学校、联系方式等；本地公开开关不能直接决定上线，必须经人工审核后进入公开数据。
5. **P1｜选手合并与身份归属不足以保证一人一页。** “同昵称＋同队伍”不能保证同一人；“这是我的页面”也不能证明归属。建立独立稳定 ID、待确认合并表及人工确认记录，未确认不合并、不覆盖。
6. **P1｜审核缺少可复核基准。** 每份审核绑定提交 SHA、文件范围、截图与验证结果；关闭问题需逐项附修改证据。新增数据/schema 审核门，不能等页面完成后才查事实。
7. **P1｜大纲现状与实现边界需统一。** §3.2“无 Git 仓库”与 §6“已建 private 仓库并推送”冲突；修正状态。另将导航、分享、自填标为“视觉占位／本地原型／已实现”，避免把 `href="#"`、`span` 当作可用功能。

## 3. UI 审美

**排名：B 战报白 ＞ A 夜战金 ＞ C 潮流贴纸。推荐 B 为全站主方向，C 的贴纸元素仅用于分享卡和卡墙。**

| 方向 | 评价 | 使用建议 |
|---|---|---|
| **A 夜战金** | 层级清楚，比分、选手卡、时间线容易区分；但金色同时强调按钮、统计、标签和时间，重点分散，整体辨识度偏常见游戏数据站。比分缺少双方名称。 | 可作为深色备选；减少金色覆盖面，优先强调主操作与关键结果。 |
| **B 战报白** | 报头、印章、细线与表格形成完整语言，最适合战报和可追溯档案。问题是辅助字过小、纸纹贯穿全文、缺导航与明确入口。 | 推荐主方向；保留报头与编辑排版，正文改用更易读的无衬线字体。 |
| **C 潮流贴纸** | 远看最醒目，适合分享；但粗边、硬阴影、旋转、点阵和多种强调色同时出现，阅读负担较高。“6:03 没了”有调侃败方的风险，建议改成中性事实。 | 用于独立分享模板；全站正文减少装饰，不直接沿用整套视觉强度。 |

具体改进：

1. **字级统一。** 三版大量文字仅 9–11px。建议正文 14–16px、辅助信息至少 12px、模块标题 18–20px；来源说明不能靠极小字退到不可读。移动导航与按钮预留至少 44px 高的点击区域。
2. **B 的纸感做减法。** 保留 `#f2ecdd` 页面底色与 `#fbf7ec` 内容底色；表格和正文区域移除横向纹理。红色集中用于栏目标题和印章，保证数字与正文阅读稳定。
3. **重新标明比分语义。** 将“FINAL SCORE／3:17”改为“本场击杀数”并显示已确认的双方游戏队名或阵营。区分击杀数与系列赛局分；A/C 的 `3/3/0` 标签改为“K / D / A”，避免与计算后的 KDA 比值混淆。
4. **补窄屏与长内容布局。** 三版均以 `max-width:390px` 为主，尚不能证明手机布局成立。验证 320、390、430px；B 的昵称与位置允许换行，C 的编号贴纸避让长昵称，导航不挤压品牌。
5. **分享图单独设计。** 不截整张长网页。制作如 1080×1440 的选手卡模板，只放昵称、明确范围的游戏数据、样本量、核实状态和来源入口；移除导航与按钮。未经确认的标签、奖励和日期不得进入分享图。
