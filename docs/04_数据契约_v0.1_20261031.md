# 04 最小数据契约 v0.3（2026-10-31，待 Codex 复审）

> 用途：让网站能表达「多阶段赛事、临时/拍卖组队、BO 多局、历史名单、构想中的未来赛事」，同时不把构想写成已定规则。
> 原则：**单一数据源 → 生成静态页**；页面不手写数据；契约不通过不进样板实现。
> 版本：v0.3，在 v0.2 基础上关闭 `reviews/codex_review_04b.md` 的两项阻断（状态组合与内部排期、规则集占位引用）。

## 1. 实体与关系

```
SourceRef（来源）
   ↑ 被所有公开数字引用
Person（人物，稳定 ID）
RosterSnapshot（名单快照，绑定 Event/Phase/Team）── RosterEntry（人 + 位置 + 状态）
Team（队伍，名称历史）
Event（赛事/活动）── Phase（阶段，可覆盖赛制/组队/规则）
   └── Match（对阵；引用双方名单快照；BO 几）── Game（单局；单局击杀比分）
                                                   ├── PlayerGameStat（单局选手数据）
                                                   └── TimelineEvent（击杀/推塔/资源）
Announcement（公告，可挂 Event 或全站）
Ruleset（规则集 + 版本；历史与未来赏金赛分开）
```

约束：
- **名单快照必须被 Match/Game 引用**，否则无法还原某场出场名单。
- Match 的 `result` 用**赢局数**，Game 用**单局击杀比分**，两者不混。
- 阶段可以覆盖赛制/组队/规则；Match 的 `format` 可再覆盖阶段。
- 活动类别（category）、阶段（phase.kind）、组队方式、淘汰方式、BO 局数、规则集版本是独立字段。

## 2. 四个独立维度（不共用一个状态字段）

### 2.1 `publish_status`（方案是否获准发布）

| 值 | 含义 |
|---|---|
| `concept` | 构想，尚非已公布规则 |
| `pending` | 方案待确认 |
| `announced` | 已公布 |
| （无 archived） | 归档不是发布状态，见 2.2 |

### 2.2 `archive_status`（记录分类）

| 值 | 含义 |
|---|---|
| `active` | 当前参赛/运营中的赛事或方案 |
| `historical` | 历史赛事/历史方案，保留展示 |
| `archived` | 不再展示或仅供内部追溯 |

### 2.3 `progress_status`（赛事进行到哪）

`tbd` / `scheduled` / `live` / `completed` / `cancelled`

### 2.4 公开展示规则（生成器必须执行）

**内部记录 vs 公开字段**：Event/Phase 各有一组「公开字段」（`public_schedule_status`、`public_start_at`、`public_end_at`）与一组「内部字段」（`internal_plan_note`、`internal_planned_start_at`）。内部字段只进内部数据，**生成器不得渲染**。concept/pending 状态可以内部排期，但公开展示一律走下方规则。

**基础判定（按顺序，命中即停）**：
1. `archive_status=archived` → 不进入公开页。
2. `publish_status=concept` → 显示「筹备方案，尚未公布」；不渲染日期/倒计时/报名/奖金/规则细节。
3. `publish_status=pending` → 显示「待确认」；只渲染有来源且 `verification_status=confirmed` 的字段；日期/报名/奖金/规则细节默认不渲染。
4. `publish_status=announced` → 按 `public_schedule_status` 与 `progress_status` 展示：日期仅在 confirmed 时渲染；报名仅在公告明确且来源 confirmed 时渲染；奖金仅在来源 confirmed 时渲染；规则细节只展示已公布版本。
5. `progress_status=completed` → 显示「已结束」；历史赛事加「历史赛事」标识。

**组合矩阵（覆盖全部允许组合）**：

| publish_status | archive_status | 展示 |
|---|---|---|
| concept | active / historical | 「筹备方案，尚未公布」；仅标题+摘要 |
| pending | active / historical | 「待确认」；仅已确认字段 |
| announced | active | 「即将开始 / 进行中 / 已结束」按 progress_status；日期 confirmed 才显示 |
| announced | historical | 「历史赛事 · 已结束」+ 战报链接 |
| 任意 | archived | 公开页不构建；内部可追溯 |

**兜底规则**：未在矩阵出现的组合，按最保守方式处理（只显示标题 + 状态 + 来源说明，不显示日期/报名/奖金/规则细节），并输出构建告警；不得静默渲染。

## 3. 最小字段表

### 3.1 Person

`person_id`（稳定 ID，`p_0001`）；`display_name`；`nickname_history[]`；`identity_status`（confirmed/candidate/pending）；`merged_into`（null 或 person_id，合并需 `confirmed_by/confirmed_at/evidence_ref_id`）；`privacy_flags[]`。

### 3.2 Team

`team_id`；`name`；`name_history[]`（只追加）；`team_status`（confirmed/candidate）。历史赛事中的队名用当时名称，不改写。

### 3.3 Event

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `event_id` | string | 是 | 稳定 ID |
| `title` | string | 是 | 名称 |
| `category` | enum | 是 | `formal_league` / `bounty_event` / `ranked_night` / `other`（活动类别） |
| `data_origin` | enum | 是 | `official` / `historical_export` / `concept` / `demo`；S1/S2 = `historical_export` |
| `publish_status` | enum | 是 | concept / pending / announced |
| `archive_status` | enum | 是 | active / historical / archived |
| `progress_status` | enum | 是 | tbd / scheduled / live / completed / cancelled |
| `ruleset_id` | string | 是 | 规则集版本 |
| `default_team_formation` | enum | 是 | fixed / auction / random_matching / invited / unknown |
| `default_stage_format` | enum | 是 | round_robin / single_elim / double_elim / one_day / unknown |
| `default_match_format` | enum | 是 | bo1 / bo3 / bo5 / bo7 / unknown |
| `public_schedule_status` | enum | 是 | confirmed / tbd（公开日期是否确认） |
| `public_start_at` / `public_end_at` | string/null | 否 | 可公开的 ISO 时间；tbd 时 null |
| `internal_plan_note` | string/null | 否 | **内部排期备注，永不渲染到公开页** |
| `internal_planned_start_at` | string/null | 否 | **内部日期，永不渲染到公开页** |
| `summary` | string | 否 | 一句话；受显示规则约束 |
| `source_ref_id` | string | 是 | 来源 |

### 3.4 Phase（阶段）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `phase_id` | string | 是 | 稳定 ID |
| `event_id` | string | 是 | 所属赛事 |
| `kind` | enum | 是 | preseason / regular / playoffs / one_day / qualifier / other |
| `order` | int | 是 | 展示顺序 |
| `window_status` | enum | 是 | confirmed / tbd |
| `stage_format` | enum/null | 否 | 覆盖 Event.default_stage_format；null = 继承 |
| `match_format` | enum/null | 否 | 覆盖 Event.default_match_format；null = 继承 |
| `team_formation` | enum/null | 否 | 覆盖 Event.default_team_formation |
| `ruleset_id` | string/null | 否 | 覆盖 Event.ruleset_id |
| `public_schedule_status` | enum | 是 | confirmed / tbd |
| `public_start_at` / `public_end_at` | string/null | 否 | 可公开的 Phase 时间窗 |
| `internal_plan_note` | string/null | 否 | 内部备注，永不渲染 |
| `source_ref_id` | string | 是 | 来源 |

继承规则：Phase 字段为 null 时继承 Event；Match.format 优先于 Phase.match_format。

### 3.5 RosterSnapshot（名单快照）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `snapshot_id` | string | 是 | 稳定 ID，如 `rs_s2_osu_v1` |
| `event_id` | string | 是 | 绑定赛事 |
| `phase_id` | string/null | 否 | 阶段级名单时填 |
| `team_id` | string | 是 | 队伍 |
| `version` | string | 是 | 快照版本（只追加） |
| `created_at` | string/null | 否 | 建立时间；不确定为 null |
| `status` | enum | 是 | `confirmed` / `candidate` / `superseded` |
| `source_ref_id` | string | 是 | 依据（报名表/公告/截图） |
| `entries` | array | 是 | 每项：`person_id, role, role_status(confirmed/candidate/unknown), joined_at` |

### 3.6 Match（对阵）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `match_id` | string | 是 | 稳定 ID |
| `event_id` / `phase_id` | string | 是/否 | 所属赛事/阶段 |
| `round` / `bracket_slot` | int/null | 否 | 轮次/对阵图位置 |
| `team_a_id` / `team_b_id` | string | 是 | 双方 |
| `format` | enum | 是 | bo1 / bo3 / bo5 / bo7 |
| `team_a_roster_snapshot_id` / `team_b_roster_snapshot_id` | string | 是 | **必须引用名单快照** |
| `public_schedule_status` | enum | 是 | confirmed / tbd |
| `public_scheduled_start` | string/null | 否 | tbd 时 null |
| `result` | object | 否 | `{winner_team_id, series_score:{team_a_wins, team_b_wins}, status: pending/confirmed}`（赢局数，不是击杀比分） |

### 3.7 Game（单局）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `game_id` | string | 是 | 稳定 ID |
| `match_id` | string | 是 | 所属对阵 |
| `game_no` | int | 是 | 第几局 |
| `winner_team_id` | string/null | 否 | 未确认可空 |
| `team_kills` | object | 否 | `{team_a: 3, team_b: 17}` **单局击杀比分** |
| `duration_clock` | string/null | 否 | 游戏内最后可见时间（如 `06:03`） |
| `stats_status` | enum | 是 | complete / partial / pending |
| `actual_team_a_roster_snapshot_id` / `actual_team_b_roster_snapshot_id` | string/null | 否 | 实际出场名单与 Match 不同时引用；null = 用 Match 的 |
| `source_ref_id` | string | 是 | 结算/录像依据 |

### 3.8 PlayerGameStat

`stat_id`；`game_id`；`person_id`；`team_id`；`role`；`role_status`（confirmed/candidate/unknown）；`kills/deaths/assists`；`participation`（可空）；`win`；`source_ref_id`；`verification_status`（confirmed/unverified/disputed）。

### 3.9 TimelineEvent

`timeline_id`；`game_id`；`clock`（游戏内时间）；`clock_status`（confirmed/pending）；`type`（kill/tower/objective/base）；`team_id`/`person_id`（可空）；`attribution_status`（known/unknown）；`description`（中性）；`evidence_ref_id`。

### 3.10 Announcement

`announcement_id`；`event_id`（可空）；`title/body`；`publish_status`（draft/published）；`date_status`（confirmed/tbd）；`published_at`（可空）；`source_ref_id`。

### 3.11 Ruleset

`ruleset_id`；`version`；`title`；`category`；`status`（historical/concept/announced）；`source_ref_id`。
历史赏金赛与未来赏金赛必须不同 `ruleset_id`；BO 局数不进 Ruleset。

### 3.12 SourceRef

`source_id`；`kind`（screenshot/video/spreadsheet/document/manual/api）；`locator`；`source_date`（可空）；`captured_at`（可空）；`verified_status`（confirmed/partial/unverified）；`notes`。

## 4. 校验规则（生成器必须执行，违反即构建失败）

1. `publish_status` / `archive_status` / `progress_status` 是三个独立字段，不得合并。
2. `publish_status=concept` → `public_schedule_status=tbd`、公开日期为空；页面不得出现「报名中」；内部字段不得渲染。
3. `archive_status=archived` 的记录不进入公开页。
4. 公开页面上的每个数字必须有 `source_ref_id`；`verification_status/clock_status/role_status` 不是 confirmed 时，渲染器必须显示「待核实/待确认」，不能只显示数值。
5. 未确认值只放在带 `*_status` 的字段里；状态字段缺失视为构建失败。
6. Match 的 `result.series_score` 是**赢局数**；Game 的 `team_kills` 是**单局击杀比分**。两者不得互相填充。
7. BO 自洽：`bo1/bo3/bo5/bo7` 的赢局数上限分别为 1/2/3/4；未完成 BO 必须 `result.status=pending` 且赢局数未达上限；已完成 BO 必须有一方达到上限；BO7 同样规则。
8. Match/Game 必须引用名单快照；快照只追加 version，不覆盖；`superseded` 快照仍可被历史比赛引用。
9. `data_origin=historical_export`（S1/S2）不得生成正式赛季字段/页面；`season_label` 概念仅在正式赛事 `data_origin=official` 时允许。
10. 队名/昵称变更只追加历史，不覆盖旧值。
11. 人物合并必须带 `confirmed_by/confirmed_at/evidence_ref_id`；未确认不合并。
12. `public_schedule_status=confirmed` 必须有来源；否则只能 tbd；内部日期不得冒充公开日期。
13. 单场数据不得直接生成长期实力评分字段；评分命名空间在评分备忘录获准前不存在于公开数据。
14. 数据文件带 `schema_version`；引用缺失（source/team/person/roster/phase）即构建失败。
15. 任何被引用的 `ruleset_id`（含占位 `to_be_decided`）必须在 `rulesets` 中存在；占位规则集 `status` 必须为 `concept`，不得渲染为已公布规则。

## 6. 待 Codex 复审的点

1. 三状态维度 + 显示规则是否够用。
2. BO 比分口径与校验是否覆盖 BO7/未完成。
